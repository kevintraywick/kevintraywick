# NYC 2026 Map — Plan and Build Record

**Goal:** Turn nyc2026.kevintraywick.com into a map that two people who are not computer people can use without being told how, then reuse it for a second traveller.

**Architecture:** A standalone Express static server (`nyc2026/server.js`) serving hand-written files from `nyc2026/public/`. No build step. Leaflet from a CDN, plain OpenStreetMap tiles greyed in CSS, walking times and routes from the FOSSGIS foot router, weather from Open-Meteo, invoices with jsPDF. Railway service `nyc2026` auto-deploys from `main` when `nyc2026/**` changes.

**Design:** see `docs/superpowers/specs/2026-11-11-nyc2026-map-design.md`.

---

## File structure

```
nyc2026/public/
  index.html      — the trip map's shell: header, map, pane, legend
  places.js       — the trip's data: HOTEL, SHOW, PLACES, EATS, TRIP
  nyc.js          — all behaviour, shared by both maps
  nyc.css         — all styles, shared by both maps
  invoice.js      — the Guido & Sons invoices and receipts
  subway.js       — subway lines as a global (works off file://)
  img/<id>.webp   — 320px square photos for the trip's places
  wendy/
    index.html    — Wendy's shell (loads ../places.js, wendy.js, ../nyc.js)
    wendy.js      — her data, and the PAGE object that configures nyc.js
    img/<id>.webp — photos for her places
```

## How the shared script is configured

`nyc.js` uses `PAGE` when a page defines one and the trip globals when it does not:

| `PAGE` field | Purpose |
|---|---|
| `hotel`, `show`, `places`, `eats`, `trip` | The data, same shapes as `places.js` |
| `from`, `nearest`, `kind`, `month`, `normals` | Wording and the weather fallback |
| `farLabel`, `nearLabel` | Turns on the Include Manhattan link and names its two states |

A place with `far:true` stays off the map until the link is pressed. A place with `pick` is starred on a `PAGE` map; a place with `best` is starred on the trip map.

**Any change to `nyc.js` or `nyc.css` must be checked on both pages.**

## Things that are easy to break

1. `spread()` nudges overlapping marks apart on every zoom; without it some cannot be reached. It only considers marks that are on the map.
2. `intent()` delays hover (70 ms, 220 ms with a pane open, 450 ms once a mark was clicked).
3. `PANE` in `nyc.js` must match the 380px pane width in `nyc.css`.
4. Walking minutes come from one router `table` request for all places; estimates show as "About N" until it answers.
5. The desktop pane rule lives inside `@media (min-width:761px)` so it cannot out-rank the phone sheet.

## How to check a change

```bash
cd nyc2026 && npm install && PORT=8873 node server.js
```

```bash
chrome --headless --virtual-time-budget=9000 --window-size=1440,900 \
  --screenshot=out.png "http://localhost:8873/#met"          # trip map, a pane open
chrome --headless --virtual-time-budget=9000 --window-size=1440,900 \
  --screenshot=out.png "http://localhost:8873/wendy/#met"    # Wendy's, Manhattan included
```

`#<id>` opens a place directly. After a push, confirm the live files changed by fetching them; Railway takes about a minute.
