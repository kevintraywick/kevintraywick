# 160 Weldon

Notes for Claude Code when working in this folder. Moved here from the root `CLAUDE.md` so they load only when needed.

**160 Weldon** (`weldon/` + `weldon-api/`, live at `160weldon.kevintraywick.com`): House-info site + API for 160 Weldon Dr — a **standalone** Railway service (project `inspiring-optimism`, GitHub auto-deploy: rootDir `weldon-api`, watch `weldon-api/**`), NOT part of the Vite build. Site source of truth is `weldon/site/`; sync before committing: `rsync -a --delete weldon/site/ weldon-api/site/`. Backend is Express + better-sqlite3 + Anthropic SDK (`weldon-api/server.js`), volume at `/app/data`. The whole site sits behind an emoji gate (signed cookie via `POST /api/gate {"picks":[...]}`; live code in Railway var `GATE_CODE`, repo default is dev-only; `/assets/favicon.svg` is exempted). Unified intake `POST /api/documents`: claude-sonnet-5 reads a scan (image or multi-receipt PDF) and returns an **array** of classified documents — receipts → `expenses`, utility-bill/tax/insurance → `utility_bills`; a receipt with no legible total is filed at $0 and flagged red in the ledger (`tr.incomplete`, clears when the amount is edited). Scan calls stream with `max_tokens: 64000` — on sonnet-5 `max_tokens` caps adaptive thinking + JSON **combined**, so a small cap fails intermittently with "No readable result from the scan"; don't lower it. Local test pattern: `DATA_DIR=<scratch> PORT=8899 node server.js` with `ANTHROPIC_API_KEY` from `railway variables --service weldon-api --json`, then curl with the gate cookie jar (a server backgrounded with `&` isn't reachable by `kill %1` from a later tool call — shell state doesn't persist between them — so free the port with `lsof -ti:8899 | xargs kill -9` instead). Synthetic multi-receipt test PDFs: one-doc-per-page HTML → `chrome --headless --print-to-pdf`. Backups: private repo `kevintraywick/weldon-backups` pulls `GET /api/backup` (bearer `BACKUP_KEY`, gate-exempt) weekly via GitHub Action — Railway volume backups are Pro-gated, don't retry them. Photo uploads are recompressed to webp (sharp, 2400px cap); receipt/document scans are stored as uploaded. The expenses ledger inlines recurring bills as blue rows (`tr.bill`): record-book + scanned utilities, plus tax/insurance amortized 1/12/mo ("est." chip until a real annual statement is scanned); the dashboard "Cost per month" tile is the trailing-12-month sum of those pieces. Duplicate intake: `/api/documents` returns suspected duplicates in `suspects` (NOT inserted) + `scan_file`; drop zones `confirm()` per item and post the user's choice to `POST /api/documents/confirm` (receipts add-anyway, bills replace via `replaceId`). Receipt dup match must be vendor-loose (`TRIM(vendor) COLLATE NOCASE` + exact amount/date) — the same receipt scans to different vendor casing run to run. Uploads accepted to 32MB (Claude's PDF request ceiling; also 100 pages max) — base64 inflates ~33%, so PDFs >20MB (`SCAN_INLINE_MAX`) go via the Anthropic Files API (beta `files-api-2025-04-14`, deleted after the scan). iPhone HEIC drops are converted to JPEG on arrival (`normalizeHeic`, `heic-convert` pkg) on the documents/photos/paint-chips routes — sharp's prebuilt libvips and the Claude API both reject HEIC (an unconverted HEIC photo only displays in Safari). A receipt with a hand-marked line item (circled / highlighted / underlined / starred) files ONLY the marked items' line-price sum — the `marked` flag in the doc schema, "(marked item only)" appended to the description; a mark on the total line doesn't count. Ledger rows carry a 🧾 link to their stored scan (`/uploads/<receipt_file|scan_file>`), retroactive since the columns were always stamped. **Expense DELETE does NOT unlink the scan file** — multi-receipt PDFs share one file across rows; cleanup is `sweepOrphanUploads()` (boot + daily): deletes uploads referenced by NO expenses/utility_bills/photos/paint_chips row AND older than 24h (a pending duplicate dialog holds its file in client state only) — **any new table that references uploads must join that keep-set**. Paint chips (`maintenance.html` drop zone, filename convention `paint_<room>_<store>` feeds room/store): the vision scan reads name/brand/code + a photo hex estimate, then a SEPARATE text-only call with the `web_search_20260209` server tool fetches the brand's published hex (`paint_chips.hex_source` 'official' vs 'photo' — photo estimates shift badly with indoor lighting; Ghost Whisperer read #A9AC9E vs official #CBD1D0). **Never combine web_search with the image scan in one call** (>4 min vs ~25 s text-only), and with server tools the structured-output JSON is the LAST text block (`content.filter(text).pop()`). A chip drop matching an existing chip's normalized filename or color name returns `{suspect, match, pending}` (no insert) and the page asks "does this image replace the previous chip?" → `POST /api/paint-chips/confirm {replaceId, pending}`. Photos are deletable via the slideshow ✕ (`DELETE /api/photos/:id`; file left to the sweep). Three more pages follow the same drop-zone conventions: **Plans** (`plans` table — drawings/sketches/PDFs, no AI reading; a dropped PDF is rasterized by `pdfjs-dist` into one row per page — `filename` is the page's webp, `source_file` the kept original PDF shared by every sibling row, so **the sweep keep-set joins `source_file` too**; `POST /api/plans/:id/split` (the ⊞ button) does the same to a PDF filed whole, and an unreadable PDF falls back to being filed whole with a note. pdfjs-dist needs **node ≥ 22.13** — that's why the Dockerfile is on `node:22`; its renderer comes from the optional `@napi-rs/canvas` dep, so `npm install --omit=dev` must not become `--omit=optional`), **Local** (`references.html` — renamed from "References" 2026-07, file name kept; `contacts` table across Tradesmen/Neighbors/Nearby panes — a dropped business-card photo is read via `readScan`, or add by hand — plus an **Estimates** pane on the `estimates` table: a dropped quote/bid is read for vendor/total/scope/date, every field editable in-row, and it deliberately never touches the expenses ledger since it's money *not* spent). The Dashboard's **Records** pane (renamed from "The facts" 2026-07, static fact rows kept above the list) has the same shape for the documents behind the house — `records` table, `POST /api/records/scan` reads title/note/date off a deed/policy/survey/warranty, rows show the note on its own line with a 🧾 link to the stored file and a ✎ rename. An unreadable title falls back to the filename rather than rejecting the upload — the scan is the thing worth keeping, and **Maintenance** (`footer.js` fetches `/api/maintenance` on every page and turns the nav link red when a task is overdue). **`house.html` and `location.html` were deleted 2026-07** and the nav is down to 10 links: the Leaflet map moved onto the Dashboard as the `#map-mini` card (wheel zoom off there, and Leaflet's own attribution control now carries the OSM/Esri credit the deleted page had in prose); its "The facts" table went to the Dashboard, and the schedule, **Systems & parts**, and the **Paint, room by room** pane + `paint_chips` drop zone all live on `maintenance.html` now, in that order. The Projects ("To do") page's status **and priority/urgency** are both editable — a recurring pattern here: `js/data.js` seed data has no stable row id, so anything editable on top of it (utility bill amounts, todo status, todo priority) lives in a small table keyed by content (`todo_status` and `todo_priority`, both keyed by `room::task text`), merged over the seed at render time rather than mutating the seed. Priority needed its *own* table rather than a column on `todo_status`, whose `status` is NOT NULL — changing only a task's urgency must not invent a status for it. An override of `''` is meaningful there ("explicitly Not set") and must be distinguished from an absent row (fall back to the seed), so the client tests `raw !== undefined`, not falsiness. Hand-added tasks (`todo_items`) instead carry both fields on the row: `PATCH /api/todo-items/:id` takes `status` and/or `priority` and leaves the omitted one alone. That whole merge (seed + `todo_status` + `todo_priority` + `todo_items`) lives in **`js/common.js` as `W.buildTodos`/`openTodos`/`urgentTodos`**, not in the page — the Dashboard's **To do** pane renders urgent (High) tasks from the same function, so the two views can't drift on what "open" or "urgent" means. Dashboard grid is three 7+5 rows; adding a card there means re-balancing the spans so each row still sums to 12.

## Layout

**Layout rules for the weldon 12-column `.grid`** (`.span-7 + .span-5`, `.span-6 ×2`, `.span-12`): every time a card is added or removed, **re-balance the spans so each row still sums to 12** — a lone `.span-7` at the end leaves a visible hole, and the fix is usually to pair it or promote a neighbour to `span-12`. The Dashboard went 7+5 / 12 / 7+5 → three 7+5 rows as cards arrived; Local went three `span-4` → four `span-6`. Sizes are relative to *neighbours*, not absolute: "make it the same size as the other panes" means match the row partner, so check the arithmetic before picking a number.

## Gotchas

- **Name the decoys in a scan prompt/schema.** A page of numbers needs the field description to say which one to take: the estimates prompt spells out "bottom-line price for the job — ignore deposits, hourly rates, and optional add-ons priced separately", and a synthetic quote with a $610 optional line and a $4,000 deposit read back as the correct $13,670. Same shape as the paint-chip "official vs photo hex" and the receipt "marked item only" rules — the model follows explicit exclusions, so state them.
- **Whether a failed scan should 422 or file anyway depends on what's valuable.** An estimate with no vendor, scope *or* total is nothing but a file, so `/api/estimates/scan` rejects it. A record (deed/policy/survey) is worth keeping even unnamed, so `/api/records/scan` falls back to the filename and leaves the title editable. Decide which one the artifact is before writing the error path.
- **Verifying a gated weldon page on *prod* isn't possible from here** — reading the live `GATE_CODE` out of `railway variables` is refused by the permission classifier (correctly). Prod confirmation is therefore: deployment `SUCCESS` for your SHA + a clean boot line + build-log evidence of what changed. Functional verification happens against a local scratch `DATA_DIR`, where the dev `GATE_CODE` makes the cookie derivable.
- **Deleting a `site/*.html` page means hunting three kinds of inbound link, not one**: the duplicated `<nav>` block on every page, prose links in `.page-title` copy, and `.more` links inside cards (the Dashboard's "Full map →" pointed at the deleted Location page). Grep the bare filename and expect hits in all three. Then check whether the page's CSS is now dead (`#map`'s 520px rule went with Location) and whether it held anything not duplicated elsewhere — House's last pane moved to Maintenance rather than being deleted with it. Deleting from `weldon/site/` needs `git rm` there *and* `git add -A -- weldon-api/site` for the mirror: the rsync removes the file from disk, but a pathspec that only names existing files won't stage the deletion, and prod keeps serving the page.
- **Bumping the Dockerfile's node major means checking the native prebuilds first.** `node:22-bookworm-slim` has no python/gcc, so any dep without a prebuild for that ABI fails the image build outright. Verify before pushing: `curl -s https://api.github.com/repos/WiseLibs/better-sqlite3/releases/tags/v<ver> | grep node-v` — `node-v127` is node 22, `node-v115` is node 20. sharp and `@napi-rs/canvas` ship N-API binaries and don't care about the node version.
- Never exercise a prod **insert** route to test (a `/api/documents` test scan filed a real $52.03 row on the live weldon ledger, and the permission classifier rightly blocks the cleanup DELETE). Test against a local server on a scratch `DATA_DIR` — the weldon gate cookie is derivable from the dev `GATE_CODE` (`HMAC(sha256('weldon-gate:'+code), 'weldon-open')`).
- `site/*.html` pages duplicate the full `<nav>` block raw — no shared partial/include. Adding or renaming a nav link (or deleting a page) means editing all 10 pages identically; grep for `navlink` to find them all.
- When the claude-in-chrome extension isn't connected, `jsdom` (already in the main repo's `node_modules`) can load a **whole weldon page** and drive it against a local scratch server — the standard way to verify a change here, and good enough to catch dead links, layout math, render output, and click/change handlers. Throwaway harness recipe (delete the script afterwards; it must live under `/Users/moon/kevintraywick/` so `node_modules/jsdom` resolves):
  - **Inline the local module scripts before parsing** — jsdom won't fetch `<script src="js/api.js">`, and the page's own inline script runs *during* parse, so injecting `api.js` afterwards throws `WAPI is not defined` and kills the process. String-replace each `<script src="js/…">` with `<script>`+file contents, and drop `footer.js` (it only sets the gate hint).
  - **Pass the gate by wrapping fetch**, no login needed: `w.fetch = (u, o) => fetch(new URL(u, BASE), {...o, headers: {...o.headers, cookie}})` with the cookie from the curl jar.
  - **Polyfill in `beforeParse`**: `fetch`, `Element.prototype.scrollIntoView`, `matchMedia` (photos.html throws without it), `confirm`/`prompt` (return the value a test wants).
  - **`dom.window.close()` when done with each page** — a page with a running timer (the photos slideshow) otherwise keeps the process alive and the run hangs until the tool timeout.
  - Drive a `<select>` by setting `.value` then dispatching `new dom.window.Event('change', {bubbles: true})`; a button by `new dom.window.MouseEvent('click', {bubbles: true})`.
  - **CDN scripts never load**, so `L` (Leaflet) is undefined. Guard the page's own code with `if (typeof L === 'undefined') return;` — that makes the harness quiet *and* the page CDN-outage-safe. Stubbing `L` yourself produces errors from the gaps in your stub (`openPopup` of undefined), which are easy to misread as page bugs.
