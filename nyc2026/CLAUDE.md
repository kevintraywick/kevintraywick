# NYC 2026

Notes for Claude Code when working in this folder. Moved here from the root `CLAUDE.md` so they load only when needed.

**NYC 2026** (`nyc2026/`, live at `nyc2026.kevintraywick.com`): a **standalone** Express app (own `package.json`, NOT part of the Vite build) for the December 4–7 2026 New York trip with Amy and Lisa, who aren't computer people — **every change is judged on "would they get it without being told"**. History: a cost-ballpark trip picker until 2026-09-18 (`7b17e9c`), then a places & eats guide with tile columns, a route builder and a day timeline (`a0773db`), and since **2026-11-10 a full-screen map**: the tile columns, Build-route toggle, timeline, add-a-place tiles and shared plan are gone from the page. `server.js` still serves `GET`/`PUT /api/state` (the old shared plan, `DATA_DIR/plan.json`) but **nothing calls it any more**. Files in `public/`: `places.js` (the data — `HOTEL`, `SHOW`, `PLACES`, `EATS`, each with an `about` paragraph the information pane shows, and `TRIP`, the four day cells in the header), `nyc.js` (all behaviour), `nyc.css`, `invoice.js` (the Guido & Sons jsPDF invoices, moved verbatim), `subway.js` (the MTA lines as a global — a script tag, not a fetch, so the page still works off `file://`), `img/<id>.webp`. Kevin compared three designs (pane beside the dot / map + list / colour map with a docked pane) and **chose the grey map with the pane fixed at the far right** — a pane popping up next to the dot covered its neighbours and was jarring; at the far right the map stays put and readable. The other two pages are deleted. Things that are easy to break: (1) **`spread()`** nudges dots apart in screen pixels on every `zoomend` — Per Se and Masa share a floor and a dozen places sit within a dot's width at the whole-island zoom, so without it some dots can't be reached; the hotel/show name labels are fed in as obstacles too. (2) Hover goes through **`intent()`**: a pause before a hover counts (70ms with nothing open, 220ms with a pane open, 450ms once a dot was *clicked*), because the pointer has to cross other dots to reach the pane and the text mustn't change under it. The pane never auto-closes (✕, Esc, or a click on the map). (3) `showAll()` pads the right of the fit by the pane's width (`PANE` in nyc.js must match the 380px in nyc.css) so no dot sits under the pane; `reveal()` pans only if zooming/dragging later put the chosen dot under it (or under the phone sheet). (4) Walking minutes come from **one** FOSSGIS `table` request for all places (estimates from `PACE`/`DETOUR` until it answers, shown as "About N"); the street line is fetched per place on demand. (5) Below 761px the pane is a bottom sheet; the desktop pane rule lives inside `@media (min-width:761px)` so it can't out-rank the sheet. **Invoices** (`invoice.js`): `paid:true` on a `CREW` entry turns that person's invoice into a receipt — red crooked PAID stamp (`stamp()`: jsPDF can rotate text but not a rect, so the frame is four hand-rotated lines), $0.00 balance, Luigi's quote switches from threat to cannoli — and puts a ✓ by their name in the header; when every non-fronting person is paid, Kevin's settlement gets an ALL SQUARE stamp. To eyeball a PDF without a browser: stub `window.open` to null and `jsPDF.API.save` to capture `output('datauristring')`, decode, then `qlmanage -t -s 1000 -o dir file.pdf`. CARTO's free basemap tiles now return "API key required" — the map is plain OSM tiles greyed with a CSS filter. Leaflet is CDN-loaded and guarded by `HAS_MAP`; with the CDN down the page becomes a nearest-first list that opens the same pane. `index.html#met` opens a place directly — handy for screenshots: `chrome --headless --virtual-time-budget=9000 --window-size=1440,900 --screenshot=… http://localhost:8873/#met` (headless Chrome won't go narrower than ~500px, so test phone widths with a throwaway page of 390px iframes; block the CDN with `--host-resolver-rules="MAP unpkg.com 127.0.0.1"`). Marker events can be driven from a same-origin iframe: `contentWindow.eval('PLACES')[i].marker.fire('mouseover')`. **`/wendy`** (`public/wendy/`, 2026-11-11) is a second map on the same code for Kevin's friend Wendy's Williamsburg weekend (Nov 21–22, Pod Brooklyn, Rising Appalachia at National Sawdust): `wendy/index.html` loads `../places.js` then `wendy/wendy.js`, which defines a **`PAGE`** object (`hotel`, `show`, `places`, `eats`, `trip`, wording, `farLabel`); `nyc.js` reads `PAGE` when it exists and the trip globals when it doesn't, so a change to `nyc.js` must be checked on both pages. The Manhattan places ride along with `far:true` and stay off the map until the **Include Manhattan** link under the zoom buttons is pressed (`setWide`); on a `PAGE` map the star marker means `pick` (Wendy's Saturday dinner picks), on the trip map it means `best` (the 50 Best list). **`/demo`** (`public/demo/`, 2026-11-11) is the trip map with every personal detail made up, for showing to other people: `demo/demo.js` defines a `PAGE` (same hotel/show/places, invented dates and flights) and an **`INVOICE`** object, which `invoice.js` merges over its real defaults (`BILL`) — names, ticket numbers, amounts, flights, seats and the mailing address — so anything personal added to `invoice.js` or `places.js` later needs a made-up counterpart in `demo.js`. Railway service **`nyc2026`** in `inspiring-optimism` (GitHub auto-deploy, rootDir `nyc2026`, watch `nyc2026/**`) — created entirely over the GraphQL API (`serviceCreate` with no source → `serviceInstanceUpdate` rootDir/watch → `volumeCreate`/`variableUpsert`/`customDomainCreate` → `serviceConnect` last so the first build has the right root). **Custom domains need a `_railway-verify.<sub>` TXT record as well as the CNAME** — `customDomain.status.verificationDnsHost/verificationToken` in GraphQL gives the values; until it's added the cert sits in VALIDATING_OWNERSHIP and the site serves Railway's wildcard cert (browser "not secure"). Hover has no API; Kevin adds records by hand. Local: `npm install && PORT=8873 node server.js`.
