# Design Language Builder & Jelly UI

Notes for Claude Code when working in this folder. Moved here from the root `CLAUDE.md` so they load only when needed.

**Design Language Builder** (`public/design/`, live at `/design`): a config-driven questionnaire (all 20 design-system sections + principles, defined once in a `SECTIONS`/`DEMOS` config that drives both the form and the generated doc) built with Jelly UI. Radios / checkboxes / color-picker swatches / live example panes feed a "Create design language document" button that opens a printable standalone HTML guide (Cmd-P → PDF). Static sub-app: loads Jelly from its CDN, autosaves to localStorage, dark toggle. The "Generate example image" button is a **placeholder** — it draws a palette-based SVG + copies an image prompt; real AI images would need a backend endpoint (not built).

**Jelly UI hard-won gotchas** (dependency-free Web Components; one `<script type="module" src="https://jelly-ui.com/package.js">`; 40 elements — the real component list + attributes live only in the bundle `dist/jelly.js`, NOT the homepage, so grep it):
- Form controls are **form-associated** (`setFormValue`) → wrap them in a `<form>` and read every answer with `new FormData(form)`. This is how the generated doc harvests values.
- **`change` events are non-composed** — they do NOT cross the shadow-DOM boundary to document-level listeners (only the slider's composed `input` does), so a `document.addEventListener("change", …)` silently misses every radio/select pick (symptom: live previews never update). Track selections via `click` on `jelly-radio`, and/or attach `change`/`input` listeners on the Jelly **host** elements directly.
- **`jelly-radio.checked` IS the `checked` attribute** (`get checked(){return this.hasAttribute("checked")}`); the group's own sibling coordination can desync and leave several radios checked at once. Own the selection state yourself and re-assert exclusivity every change (toggle the `checked` attribute so only the chosen radio is on).
- Theming: **`--jelly-accent`** (fallback `--jelly-color-background-accent`) sets the checkbox/radio/select selection color; **`--jelly-fill`** sets button fill; `<jelly-theme mode="light|dark|auto">` switches theme (guard every localStorage call — an unguarded one throws on opaque origins and halts the script). `size="small|large"` scales controls.
- jsdom test trick: the page's own logic is a classic inline `<script>` (jsdom runs it) while the Jelly loader is `type="module"` (jsdom skips it) — so the app's own selState/refresh logic is fully testable in jsdom even though the Jelly custom elements never upgrade; simulate a `jelly-radio` click to verify single-select and preview reactivity without a browser.
